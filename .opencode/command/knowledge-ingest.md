description: 把粘贴/对话里的一大段知识收进 knowledge/：去重归类、脱敏、登记索引，然后提交并 push
agent: build
---

输入是 `$ARGUMENTS`，或用户这条消息里粘贴的原文（`[pasted-context-1.txt]` 一类）。

1. 先读 `knowledge/README.md` 的目录表，看有没有现成类别能装。能装就不新建；装不下才新建子文件夹，并同步目录表。
2. 逐条跟既有文件比对，重复的并进原文，不新开一份。发现分类不合理（该拆、该并、名字看不懂）就直接调整，顺手把索引改对。
3. 写文件前做最小验证：至少用一条只读命令或公开源码把关键结论复核一遍（`gh api` 取模板文件、在安装目录 grep 到对应 id、`curl` 探端点、`npm view` 查包、实跑一次看输出都行），把验证方法和结果写进文件。材料本身就是外部文档（资料库调研、上游 README）时，重点是把**实测与文档口径的差异**写出来，别整篇搬运。验不了的降级标注，不要写"已验证"。
4. 写文件：文件名自解释；每条结论标证据等级 **已验证 / 源码级 / 文档级 / 推测**，非实测为主的文件在开头写清依据哪几路、文末单列未验证项；命令优先只读版，破坏性命令写清风险与前置检查。
5. 脱敏扫描用 grep 模式跑，不靠肉眼：账号名、邮箱、仓库 URL、本机绝对路径、token 及其派生物，一律换成 `<owner>/<repo>`、`<path>`、`~/.config/<app>`。
6. 更新 `knowledge/README.md` 目录表；新增类别必加一行。
7. `git status --short` → `git add` → 提交（`docs(knowledge): …`），然后贴出 `git status --short` 与 `git log --oneline -1` 的真实输出。
8. 推送只看当前分支：在主仓库 `main` 上才 `git push origin main`；当前分支是模型分支（`<任务名>/<model-slug>`）时**只提交、不推送**，把提交留给用户回收。

不要：整篇搬教程、写没实测过的结论、往 `knowledge/` 放评测产物（那是 `evals/`）。
