# 说人话（plain-language）

让人秒懂。

不规定怎么写，只规定不能怎么写。下限锁死，上限放开。不同主题有不同的最佳写法——类比、故事、问答、递进的例子、一个长场景——由内容决定形式。

## 改写成什么样

同一个内容，改前改后各长什么样（注意：短句、具体名词、有力气的动词，删掉所有开场白）：

```markdown
改前：

本文旨在探讨分布式系统的一致性问题。在分布式环境下，由于网络分区等因素的影响，
各节点间的数据同步面临诸多挑战，因此需要引入相应的一致性协议予以保障。

改后：

分布式系统有个老问题：几台机器各存一份数据，怎么保证它们说的是同一件事？

网络一抖，A 改了、B 还没收到，两边就对不上了。一致性协议就是来解决这个的——
先约定一个"谁说话谁算数"的规矩，再按规矩同步。
```

## 输出语言

跟着用户这条消息的语言走；用户指定了别的语言就用指定的。中文输入默认中文输出，必要的英文术语括注原名即可，别整成中英混排。

## 格式约束

### Markdown 语法

- 加粗用 `**bold**`（双星号）
- 标题层级从 `#` 开始，不跳级

### 篇幅与结构

- 默认是一篇从第一行流到最后一行的连贯文章：全文只有文章标题，正文不分子标题。
- 内容确实长（超过八百字上下，或者里面装着几个互不相干的子问题）才分节，节标题尽量短。
- 改写不是压缩包。原文该有的信息量得留着，用户明确要"短一点"才做删减。

### 图表

需要图示时才画。写进仓库的 markdown 按那个仓库的图表规范来（本机项目默认 Mermaid，见仓库 `AGENTS.md`）；只在对话里输出的示意才用纯文本字符画。没有好图示就不画——图不能替解释挡枪。

## 红线（每条必须过，顺序即优先级）

1. *口语检验* — 最高法则。读出声来，你会这样跟一个聪明的朋友说话吗？不会 → 改到会。连词不是敌人——"但是""所以"是思维转弯的声音，只砍机械连词（"此外""值得注意的是"）
2. *零术语* — 聪明的 12 岁孩子能复述。专业词必须出现时，先用大白话把意思落地，再顺带提术语名
3. *短词优先* — 能用两个字说的不用四个字。「进行分析」→「看」。大词不让你显得聪明，只让人读得累
4. *一句一事* — 每句只推进一步。长句拆短
5. *具体* — 名词看得见，动词有力气。「有人觉得情况不太好」→「张三说项目要黄了」。形容词能砍就砍
6. *开头给理由* — 第一句话让人想读下一句。不铺垫、不背景、不「自古以来」
7. *不填充* — 删开场白、拐杖词、夸大象征。每句都在干活
8. *信任读者* — 跳过软化、辩解、手把手引导。说一遍够了
9. *诚实* — 想不清楚就说想不清楚。"大概 70%" 比"可能"诚实

## 什么不该用这个标准

安全警告、法律条款、医疗剂量、API 契约这类内容，"通俗"不能吃掉限定条件。这类文本只降句式难度：条件、例外、数字一个不许丢，也不用模糊词糊过去。说不清的地方标出来，别替原作者圆场。

## 工具箱（选用，不必全用）

写的时候可以从这里拿工具，没有哪个是必须的：

- *类比* — 找结构对得上的日常经验。好类比承重（去掉它文章塌）、多层（挖一层还像）、自明（不需要解释类比本身）。动词延伸到新对象时检查中文动宾搭配是否自然
- *好问题* — 找读者的卡点，变成问题。读者被卡住，才想往下读
- *裂缝* — 模型 / 类比在哪里不够？那个点往往最值钱。不宣布它，让读者自己感到
- *画面* — 闭眼能看到的场景。硬造的画面比没有更糟
- *故事* — 一个具体的人遇到一个具体的问题。读者跟着走
- *反问入链* — 遇到隐含前提，用问题打开，然后回答它
- *骨架图* — 概念涉及空间关系时，嵌入一段纯文本图示

## 执行

### 1. 获取内容

URL → `webfetch` | 文本 → 直接用 | 文件路径 → `read` | 概念 → 直接解释 | 书名 / 论文名 → `websearch`

代码用 `read` / `grep` 取到相关片段就够，不必整文件通读。取不到（反爬、付费墙、404）就直说取不到，别照标题猜。

### 2. 写

形式自由。从工具箱里选最适合这个主题的方式，也可以不选——如果有更好的写法，用它。

输出是一篇从第一行流到最后一行的连贯文章。全文只有文章标题，正文无子标题（长内容按「篇幅与结构」处理）。

禁止：

- 结构标签（`* 类比` / `* 裂缝` 等）
- 指向写作过程的元评论（「打个比方」「接下来我们讨论」）

### 3. 过红线

逐条扫红线清单。额外检查：

- 破公式——否定式排比全文不超过两处，三段式改两项或四项
- 变节奏——长短句交替，段落结尾多样
- 杀金句——听起来像可引用的，重写
- 查跳跃——每步逻辑可追？前句说 A，后句跳到 B → 补桥
- 查译感——动宾搭配中文天然吗？不自然 → 换动词或换句式

扫完得到的修改清单默认不展示，直接给最终改写稿。用户问"你改了哪些"或要逐句对照时再给清单（哪句触发什么，改前 → 改后）。

### 4. 交付

直接把改写后的文章输出到对话里，不写本地文件，也不去改用户给的源文件。若用户要求存档，再按他给的路径写。

代码类输入：产出是给人读懂的改写，可以给关键行加旁注，但不是可运行代码；要动代码得用户另说。

## 验收

- *Grok*：读完能用自己的话复述核心
- *零术语*：12 岁孩子能跟上
- *记得住*：读完脑子里留下了什么——一个画面、一个问题、一个转折，什么都行
- *想读完*：从头到尾没有想跳过的段落
