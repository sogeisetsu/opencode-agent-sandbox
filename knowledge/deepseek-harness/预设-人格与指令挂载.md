# DSH 预设：persona 与 agent-instructions 挂在哪

> 核对：2026-11-16 初版；2026-11-19 补系统提示词分段顺序、部署级/预设级落点与「风格无设置项」。依据：本机安装包（`0.2.2-rc.3` nightly）`app.asar` 内 `dsh-web-app/presets/*.patch.yml`、`dsh-web-app/cordis.patch.yml`、`dsh-base/cordis.patch.yml`，以及 `dsh-persona`、`dsh-agent-instructions`、`dsh-system-prompt` 的包内 README 与 `src/`。证据等级以**源码级**为主，界面行为未逐条实跑。DSH 为 nightly，字段与行号会漂移。复核方式：用能穿透 ASAR 的 file-read 直读上列文件（或按 `dsh-doc` 的 locate-docs 用 `ELECTRON_RUN_AS_NODE=1` 的运行时读）；2026-11-19 按此复核到 `dsh-web-app/cordis.patch.yml:19`、`dsh-base/cordis.patch.yml:528`、`dsh-agent-instructions/src/index.ts:47/131/181`、`dsh-agent-instructions/README.md:158/222`。

## 结论

一个「模式」（Agent 预设）= 一条 `@deepseek-ai/dsh-agent-preset` 声明 + 该声明里的一串子插件行（`config.plugins`）。`persona` 与 `agent-instructions` 是其中两行，**按会话生效**，不是全局插件。

- 没有 `persona` 行，预设只能换工具、换不了身份。
- 没有 `agent-instructions` 行，那个模式**根本不读 AGENTS.md**——极简模式就是这种情况。
- `persona` 只能挂在预设组装内：挂到全局会与提示词注册表自带的 `deployment:persona-prefix` 注册撞名，直接报错（包内 README 原话：*mounting it globally collides with the prompt registry's own persona registration and fails loud*）。

## 两行分别管什么

| | `dsh-persona` | `dsh-agent-instructions` |
|---|---|---|
| 本质 | 预设配置里的一段文本 | 磁盘 Markdown 的加载器 |
| 谁写 | 预设作者 | 用户自己 |
| 注入位置 | 系统提示词开头（`deployment:persona-prefix`，order 0） | 首条用户消息里的 `<system-reminder>` 基线 |
| 管什么 | 「你是谁」（身份、语气） | 「该遵守什么约定」（个人/项目规则） |

### persona 的配置与遮蔽语义

| 字段 | 默认 | 作用 |
|---|---|---|
| `prefix` | 必填 | 人设前缀，替代部署级人设 |
| `suffix` | `''` | 人设后缀（order 10200）；省略或留空会**遮蔽**部署级后缀，不是继承 |
| `complete` | `false` | 只用前缀当整个系统提示词，其他段落全部丢弃 |
| `includeRuntimeContext` | `true` | `false` 时不评估可选运行时上下文；必需上下文（cwd、子代理身份等）仍注入 |

- `prefix`/`suffix` 是模板：`{{…}}` 在**渲染期**按已注册的提示词变量解析，`{{model}}` 即当前模型名。
- 部署级人设不在这行，而在 `system-prompt` 行的 `personaPrefix`；`persona` 行的作用是**遮蔽**它。Web 层也把部署级那句设成同一文本（`You are a coding agent powered by the {{model}} model.`）。

### 两个槽位在系统提示词里的位置

`prefix` 不是提示词的第一句，它前面还有固定开场白；`suffix` 则在最末，排在环境信息之后：

| 顺序 | 段落 | 来源 |
|---|---|---|
| −1000 | `You are an AI agent powered by DeepSeek Harness.` | `system-prompt` 的 `includeHarnessIdentity`，**不是** persona |
| 0 | persona **prefix**（含「powered by the {{model}} model」那句） | `persona` 行 / `system-prompt.personaPrefix` |
| 中间 | 第一方指引：工具 SDK、结构化输出要求等 | 各插件自己的 section |
| 10000 | harness 源码路径 | 环境段落（section） |
| 10100 | Web 界面地址 | 环境段落（section） |
| 10200 | persona **suffix** | `persona` 行 / `system-prompt.personaSuffix` |

所以 suffix 的用途是「收尾叮嘱」：它排在模型读完所有工具说明之后、进入对话之前的最后几行。省略或空，就是该槽位被遮蔽、什么都不渲染。

- **模板变量的边界**：`{{model}}` 由 agent loop 提供；`{{cwd}}` **不是**已注册变量。把 `Your working directory is {{cwd}}.` 这类句子留在 `suffix` / `personaSuffix` 里，系统提示词组装会直接报错（未解析变量 fail loud）；cwd 由 working-directory 服务作为必需上下文注入。
- `complete: true` 时只保留渲染后的 prefix 作为整个系统提示词：suffix 一并忽略，各插件的 section 也不进系统提示词。但 AGENTS.md 不在此列——它走的是消息通道，不受 `complete` 影响。

### agent-instructions 只补两点

链的解析、注入形态、刷新与预算细则见 [工作区、会话与指令链](工作区-会话与指令链.md)，本篇不重复：

- `maxBytes` 按「用户全局链」「项目链」**分别**计，两条都有时整条消息最多 2×。
- 单文件源上限 `maxSourceBytes` 默认 1 MB。

## 四个内置预设的实际挂载

`dsh-web-app` 自带四个，`order` 决定界面里的顺序：

| 预设 | order | persona | 读 AGENTS.md | 工具面差异 |
|---|---|---|---|---|
| `standard` | 1 | `You are a coding agent powered by the {{model}} model.` | 是，`maxBytes: 65536` | 全量（含 office、subagent/workflow、plan mode） |
| `ptc` | 2 | 同 standard | 是，65536 | 执行器换成 `tool-executor-ptc`；`workflow-ptc`、`tool-workflow` 两行 `disabled: true` |
| `minimal` | 3 | `You are a helpful software engineer assistant.` + `complete: true` + `includeRuntimeContext: false` | **否**（没有这一行） | 只剩终端（bash/pwsh 持久会话）与压缩；文件工具关掉读写（`read`/`write`/`edit` 均 false，只留 `readImage`） |
| `cordis` | 4 | standard 那句 + `You help the user customize DeepSeek Harness itself.` | 是，65536 | 比 standard 多 `tool-cordis`、少 office |

树形（以 standard 为例，省略工具行）：

```yaml
- id: preset-standard
  name: '@deepseek-ai/dsh-agent-preset'
  config:
    id: standard
    order: 1
    plugins:
      - id: persona
        name: '@deepseek-ai/dsh-persona'
        config:
          prefix: You are a coding agent powered by the {{model}} model.
      - id: agent-instructions
        name: '@deepseek-ai/dsh-agent-instructions'
        config:
          maxBytes: 65536
      # …工具、plan-mode 组、压缩组等
```

「编码 Agent 人格」指的就是 `prefix` 那句固定文本——一句身份声明，不是性格设定。极简模式换成另一句并 `complete: true`，系统提示里就只剩那一句。

## 部署级还是预设级：改哪一层才生效

人设有两个落点，优先级是**预设级 > 部署级**：

| 层级 | 落在哪 | 谁在写 |
|---|---|---|
| 预设级 | `preset-<id>` 行的 `config.plugins` → `id: persona` | 预设作者；Web 编辑器保存时按 id 覆盖，写进 profile patch |
| 部署级 | `system-prompt` 行的 `personaPrefix` / `personaSuffix` | 部署层：`dsh-base` / `dsh-web-app` 的 bundle patch，或 profile patch |

本机 0.2.2-rc.3 实读值：`dsh-base` 里 `personaPrefix: ''`；`dsh-web-app/cordis.patch.yml` 把它改成 `You are a coding agent powered by the {{model}} model.`；两者都没设 `personaSuffix`（默认 `''`）。四个内置预设每个都挂了自己的 `persona` 行，**prefix 为空也只是遮蔽**，所以改部署级那句对现有四个模式没有任何可见效果——想改人设必须落到具体预设。

落点澄清：preset 不是独立文件，而是 profile 配置树里的一行（`preset-<id>`），所以预设级 persona 最终也写在 `~/.dsh/profiles/<profile>/cordis.patch.yml`；该文件里的 `agent-preset-registry` 行决定默认用哪个模式（本机 `default: standard`）。手写覆盖 `preset-<id>` 时注意 patch 对 `config` 是**整段替换**：必须抄全整个 `config.plugins`（工具、plan mode、压缩组都在里面），只写 persona 会把该模式的工具面重置。

## 默认层被关掉这件事

`dsh-base` 里本来就有 `agent-instructions` 行（`maxBytes: 65536`），但 `dsh-web-app` 的 bundle patch 把宿主那条 `disabled: true`，改由四个预设各挂一份。所以 Web 端实际生效的是**预设里那一行**；基座那行留给不经过 `dsh-web-app` 的 profile。

推论：想改某个预设的预算或候选文件名，改的不是基座那行，而是该预设的 `config.plugins`。

## 怎么改

| 想改 | 落点 |
|---|---|
| 规则内容 | `~/.dsh/AGENTS.md`（用户全局）或项目/工作区根的 `AGENTS.md`；同名 `CLAUDE.md` 内容相同不会重复注入 |
| 64 KB 预算、候选文件名 | 覆盖对应预设的 `agent-instructions` 行 |
| 人格文本（含「编码 Agent 人格」） | 覆盖对应预设的 `persona` 行，或新建预设；部署级默认在 `system-prompt.personaPrefix` |
| 让极简模式也读 AGENTS.md | 给 `minimal` 预设补一行 `agent-instructions` |
| 调「回复风格」（口吻、详略、客套程度） | `~/.dsh/AGENTS.md`（所有会话）或项目根 `AGENTS.md`（该项目）；只有要固定某个模式的身份才动 `persona` 行 |

**DSH 没有「回复风格」设置项**：随包设置页覆盖 general / account / agent-loop / models / plugins / shell / subagent / web-search / session-log（`dsh-client-ui-settings-*` 包），没有风格或「自定义指令」页面。口吻只能落在 persona（系统提示词，按模式）或 AGENTS.md（会话历史里的 guidance，按工作区）这两处。

覆盖机制：内置预设的 patch 文件随包只读。预设文件头注释写明「Web 编辑器保存的修改，会按 id 覆盖这一行的 `config.plugins`，存到 profile patch」。patch 对 `config` 是**整段替换**（见 [配置分层与目录](配置分层与目录.md)），覆盖时要给出完整的 `plugins` 列表，不能只改一个键。

## 取证坑：`asar.mjs` 头部自检失败

本机实测（`0.2.2-rc.3`）：`dsh-forensics` 自带的 `asar.mjs` 读这个 `app.asar` 会直接退出：

```text
asar 头部偏移自检失败: 8+payload=5669980 / 16+json=5669977
```

原因不是归档坏了，而是脚本假设「JSON 结束后数据立即开始」；这份归档的 JSON 后有 **3 字节零填充**，把数据基址对齐到 4 字节。实测布局：

| 项 | 取值 |
|---|---|
| 数据基址 | `8 + u32@4` |
| JSON 起点 | 偏移 16 |
| JSON 字节长度 | `u32@12` |
| JSON 结束 → 数据基址 | 3 字节 `00` 填充 |

绕法：把 `asar.mjs` 复制到 `%TEMP%`，删掉那处自检，再用 `ls` / `cat` / `grep`；不要改随包脚本。

## 未核实项

- Web 编辑器改人格/预算后是否即时生效（未复测；按「预设在建会话时定死」推断需新开会话）。
- `u32@8` 的确切语义（与 `u32@12` 差 7）未还原；`u32@4 = 数据基址 − 8` 只在当前安装包上核对过，未换包对照。
- 设计过但未执行的三条「创造模式」提示词（Skill / Plan / Build）未收录；Plan 版「只写 `<工作区>/.plan/`」是提示词软约束，不是工具级限制。
