# DSH 内置计划模式（plan mode）

> 核对：2026-11-16。依据：打包产物 `dsh-plan-mode/README.md` 与四个预设 patch（**源码级**）；`/plan` 的界面操作未复测。DSH 为 nightly（`0.2.2-rc.3`），包内实现会漂移。

## 结论

- 进：`/plan`（可带一条消息与有序的图片/文件附件）；退：`/plan off`、批准审核，或提交反馈继续计划。
- **软约束，不是硬限制**：工具一个不少，靠提示词说「先别改」。要真拦，得另配沙箱模式与审批策略。
- 计划写完通过 `exit_plan_mode` 提交（plan markdown，以 `#` 标题开头），用户点 Approve 才离开计划模式。

## 状态与存储

- 持久层只有一条 **log-only 全量事件 `plan/mode`**，最后一条即当前状态；resume / fork / 压缩都靠折叠日志还原。
- 状态**跨标签页一致、跨重启保留**；fork 继承日志里的状态，新建的子代理默认 inactive。
- 开着的 turn 里改模式不会立刻落盘：变更挂起，等下一个允许的 in-turn pre-step 追加；追加失败也不会阻塞本轮。

## 审批流

| 动作 | 结果 |
|---|---|
| Agent 调 `exit_plan_mode` | 弹出审核，内容就是本次提交的 plan markdown |
| Approve | 退出计划模式，记录一个静默的「待退出」，在下一个 pre-step 追加；当前工具批次仍按计划模式引导 |
| Keep planning（可附文字） | 带反馈打回，agent 继续改计划 |
| 关掉审核直接发消息 | 结束本轮，下一条消息开启新请求，计划模式仍在 |
| 没有交互式审核通道 | `exit_plan_mode` **fail closed**，只能 `/plan off` 手动退出 |

- `exit_plan_mode` 是逐步披露的：从「当前选中的计划状态为 active」的第一步起被允许，之后整个会话都允许；进出计划模式只改引导文本，不改工具目录（为请求缓存稳定）。
- 对话里的口头同意**不算批准**：预设的引导文本明确写了「用户确认某件事不等于批准计划」，必须走 `exit_plan_mode`。
- **子代理不能开审核**：origin 为 subagent 的会话调用 `exit_plan_mode` 会失败，被要求把未决决策写进最终结果。

## 体验细节

- 进入计划模式不会「少工具」：Native 与 PTC 两种执行器看到的工具集相同。
- `/plan`、`/plan off` 这两条命令本身不进模型历史；`/plan` 后面带的内容会变成一条用户消息（附件在前、文本在后）；纯 `/plan` 不占历史 token。
- 预设的引导文本要求计划阶段**不要用 `todo_write`** 跟踪：todo 跟踪的是批准后的实施，计划本身放在 `exit_plan_mode` 里。
- 计划模式是「产品包」而非可替换的能力 seam：状态、引导、命令、退出工具都在同一个包里。

## 哪些预设带它

`standard`、`ptc`、`cordis` 三个预设都挂了 `dsh-plan-mode`；`minimal` 的预设清单里没有这一行，所以该模式不提供 `/plan`。
