# DSH 插件生态：原生四块短板、最小组合、包名核实

> 核对：2026-11-08。DSH = DeepSeek Harness。**本机未装 DSH，未逐个安装验证**；能力描述来自上游 README 与包元数据，包名与存在性用公共 npm registry 逐个 HEAD 核对（方法见文末）。标 **推测** 的未实证，标 **已核实** 的指「包存在」这一件事，不等于功能与描述一致。

## 一句话

DSH 原生的缺口集中在四处：**跨会话记忆缺失**（原生只有会话内日志）、**无自动备份**、**搜索只有 DeepSeek Search API 且按量计费**、**无插件市场与渐进披露**。最小可用组合＝侧栏底座 + 一个记忆插件 + 破坏性命令拦截 + 一个备份插件。

## 四块短板 → 该装什么

| 方面 | 推荐（功能完整） | 轻量 | 关键判断 |
|---|---|---|---|
| 文件与系统 | `dsh-better-sidebar` | `dsh-folderead` / `dsh-file-manager` | 侧栏底座整个生态的「地基」，其他插件靠它注册 Tab。只要文件预览时原生右侧栏已够 |
| 记忆与沉淀 | `dsh-memory-fortress` / EverOS 一类独立记忆运行时 | `dsh-simple-memory` | **原生只有会话内日志，跨会话记忆必须靠插件**。轻量款按会话注入索引而非全文，手动可控 |
| 定时调度 | `@michengai/dsh-automation` | `dsh-schedule-tasks` | 前者每次触发在全新 root Agent + Session 里跑完整编码任务；原生 Schedule 只适合当前对话内的提醒 |
| 搜索 | `@sheep233_/dsh-web-search-free`（Parallel + Exa 双免费后端、匿名免 Key） | `@liustack/modsearch`（Firecrawl 免 Key，装上即用） | 原生走 DeepSeek Search API 按量计费且只有一个提供方。这类插件接管内置 `web_search`，**不改使用习惯** |
| 上下文管理 | `dsh-context`（看清）+ `billion-context`（`compress` 工具瘦身） | `billion-context` 单独 | 只关心「太长能压一下」时装一个就够 |
| 安全与备份 | `cc-safety-net` + `dsh-backup` | 同左 | 前者在工具执行前拦破坏性 Git/文件系统命令与敏感文件访问；**原生没有自动备份，这是必须补的空白** |
| MCP 管理 | `dsh-mcp-manager` | `dsh-mcp-manage` | 清单/启停/编辑/健康度/就地重连/导入导出；轻量款支持**会话级懒启动** |
| 记忆管理 | `dsh-memory-manager` | 同名社区版 | **它是管理界面，不是记忆能力本身**。已有满意的记忆插件时这行可跳过 |
| MCP 渐进披露 | `dsh-mcp-gateway`（`mcp_catalog` / `mcp_search` / `mcp_describe`，不隐藏原工具） | `dsh-mcp-lazy`（server 用到才连、空闲断开、列表缓存） | **MCP 工具少于 10 个时，原生直接暴露就是最简单的** |
| 技能管理 | `dsh-skill-manager` | `dsh-project-skills-mng` | 根扫描、`_disabled` 启停、三态调用策略、批量操作、调用账本 |
| 插件市场 | `dsh-market`（600+ 插件、中文搜索） | `dsh-plugin-market`（只加一个入口按钮） | **插件管理本身原生页已覆盖安装/启停/卸载，不需要再装「插件管理插件」** |

## 三套组合

| 场景 | 组合 |
|---|---|
| 极简起步（只补硬伤） | `dsh-better-sidebar` + `dsh-simple-memory` + `cc-safety-net` + `dsh-backup` |
| 搜索零成本 | 在极简起步上换成 `modsearch`（或双免费后端的 `dsh-web-search-free`） |
| 全面托管 | 统一管理包（MCP/记忆/网关/技能四件套）+ `dsh-market` + 独立记忆运行时 + `dsh-automation` |

避免重复的三条：不装重复的「插件管理插件」；记忆管理只在想要跨后端统一视图时才装；MCP 工具少于 10 个别上渐进披露。

## 包名核实（**本次实测，与上游文档有出入**）

用 `curl -o /dev/null -w %{http_code} https://registry.npmjs.org/<urlencoded-name>` 逐个查，2026-11-08 结果：

| 结果 | 包名 |
|---|---|
| 200 存在 | `dsh-better-sidebar`、`dsh-folderead`、`dsh-file-manager`、`dsh-context`、`dsh-automation`、`@michengai/dsh-automation`、`dsh-backup`、`@xiaoyuyu6420/dsh-backup`、`dsh-skill-manager`、`cc-safety-net`、`dsh-web-search-free`、`@sheep233_/dsh-web-search-free`、`dsh-plugin-market`、`dsh-mcp-manage`、`dsh-mcp-manager`、`@liustack/modsearch`、`@yilinxiao/dsh-mcp-lazy`、`@deepseek-ai/dsh-tool-executor-ptc` |
| 404 不存在 | `dsh-simple-memory`、`@a903067276-rgb/dsh-simple-memory`、`@kenryu42/cc-safety-net`、`@omdsh-dev/dsh-better-sidebar`、`dsh-schedule-tasks`、`@mydsh/dsh-schedule-tasks`、`dsh-memory-manager`、`@sanqiuyef/dsh-memory-manager`、`@sanqiuyef/dsh-skill-manager`、`@sanqiuyef/dsh-mcp-manager`、`dsh-mcp-gateway`、`dsh-market`、`dsh-hydrasearch`、`dsh-project-skills-mng`、`billion-context`、`@ranxianglei/billion-context`、`@evermind-ai/everos`、`@mochinek0/dsh-web-search-free` |

可复现的两条结论：

1. **带上游文档给的作者作用域，约一半包名在公共 registry 上查不到**（大小写都试过：`@MyDSH` 与 `@mydsh`、`@EverMind-AI` 与 `@evermind-ai` 全 404）。所以「认准作者作用域」这条建议本身不具备可执行性——**装前用 `npm view <pkg> version` 自己核一次**，不要照抄名称。
2. 同一个插件常有「无作用域主包 + 若干 `@scope/` 镜像或加强版」并存的形态（`dsh-mcp-manager` 200，同时搜到 `@sunshaobei/`、`@xxxyz/`、`dsh-mcp-manager-plus` 等多个同族包）。选择依据应是**下载量与最近发布时间**，不是名字长短。

原因侧只能给 **推测**：DSH 插件可能另有自建分发渠道，或上游文档写作时用了未发布的占位作用域；404 既可能是「未发布到公共 npm」，也可能是「名称有误」，两者从 registry 侧无法区分。

## 验证方法

```bash
# 单个包：存在性 + 版本 + 最近发布
npm view dsh-mcp-manager version time.modified
# 纯 HEAD 批量核对（不下载、不安装）
for p in dsh-better-sidebar dsh-simple-memory dsh-backup; do
  printf '%s => ' "$p"; curl -s -o /dev/null -w "%{http_code}\n" --max-time 10 "https://registry.npmjs.org/$p"
done
# 按关键词看同族包与下载量，避免装到废弃镜像
curl -s "https://registry.npmjs.org/-/v1/search?text=dsh-mcp-manager&size=10"
```
