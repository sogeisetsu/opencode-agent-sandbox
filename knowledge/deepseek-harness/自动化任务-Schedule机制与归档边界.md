# DSH 自动化任务（Schedule）：宿主级存储、投递、状态与归档边界

> 依据与证据等级：本机安装的 DSH `0.2.2-rc.5` 自带文档（`node_modules/@deepseek-ai/dsh/docs/user/guide/schedule.zh.md`、`docs/subsystems/schedule.zh.md`、`docs/subsystems/workspace.zh.md` 及 `docs/upgrade-guide/`）＝**文档级**；本机只读调用 `schedule_list`、读取包 `package.json` 与运行时工具清单＝**已验证**。未逐项实点 GUI 交互；文末单列未核实项。不写会话里的具体任务内容、账号或绝对路径。

## 一句话

自动化任务是**宿主级（Host）Schedule 记录**，不存放在会话文本里；归档会话不会自动带走所有任务，但「有活动任务指向该会话」会挡住普通归档。

## 1. 入口与模型工具

| 项 | 结论 | 证据 |
|---|---|---|
| 创建路径 | 对话里让模型建，或侧栏「自动化任务」页 →「新建」→「手动创建」 | 文档级 |
| 模型工具 | `schedule_create`（`title`、`prompt`、`rrule`、`target`）、`schedule_list`（分页 `{items, shown, total, limit, offset}`）、`schedule_view`（按 id 读）、`schedule_edit`（`update` 改字段 / `delete`；删除不撤回已入队消息） | 文档级 + 已验证（本会话四个工具可用，`schedule_list` 只读调用返回上述分页结构） |
| preset | `standard` / `cordis` / `ptc` 声明四个工具与时钟上下文；`minimal` 都不声明；被委派的 subagent 看得见工具但调用被拒 | 文档级 |
| 版本变化 | v0.2.2-alpha.2 起 `schedule_update` / `schedule_delete` 并入 `schedule_edit`，时间统一为 RRULE + `target`；v0.2.0-rc.2 起「自动化任务」可选 bundle 移除，Web 组合直接挂载 | 文档级 |

## 2. 任务存在哪

- 任务独立于 Session 激活状态存储；`list` / `view` / `history` 都**不激活**目标会话，只有到期投递才恢复或创建会话。（文档级）
- 页面列出的是宿主**全部**任务，跨 Session；会话行与顶部时钟只是这个全局集合的视图。（文档级）
- 「一个 Session 的任务」包含两类：投递到该 Session 的，以及该 Session 的 Agent 创建或修改过的；后者即使目标在别处，仍会出现在会话的任务视图里。（文档级）

## 3. 时间规则

- 宿主求值器内部有七种权威类型：`after`、`at`、`every`、`daily`、`weekly`、`cron`、`rrule`；**面向模型的工具只接受 RRULE**，不接受时间选择器参数。（文档级）
- RRULE 形如「一行 `DTSTART` + 换行 + 一行 `RRULE`」；`DTSTART` 用 `Z` 表示 UTC 或用 `TZID` 指定 IANA 时区；固定偏移写成 `Etc/GMT-5`；不支持浮动本地时间与纯日期值。允许 `FREQ=MINUTELY|HOURLY|DAILY|WEEKLY|MONTHLY|YEARLY`、一次性用 `COUNT=1`；拒绝 `SECONDLY`。（文档级）
- 页面提供引导式选项：仅一次 / 每 N 分钟 / 每 N 小时 / 每天 / 每周 / 周一至周五 / 每月 / 自定义；自定义可填五字段 Cron 或 RRULE 文本。（文档级）
- IANA 时区下的重复规则按**本地钟表时间**走：跳过的本地时间不触发，重叠时取较早时刻。（文档级）

## 4. 投递目标与调度

| `target` | 行为 |
|---|---|
| `this_session` | 投递到当前已有会话 |
| `new_once` | 首次投递时建一个会话并复用（省略 target 时的默认） |
| `new` | 每次投递新建会话，受宿主最小间隔约束 |

- 新会话使用当前会话的工作目录与 preset，加入目录已注册的 Workspace，标题取任务名。（文档级）
- 单任务最小投递间隔 60 秒；`new` 目标可用 `newSessionIntervalSeconds` 提高上限。（文档级）
- 宿主关闭期间调度停止；重启后只补逾期的一次性任务，或每条重复任务**最近错过的一次**，不逐次重放；延迟投递不会移动规则锚点。（文档级）
- 回执只证明消息**已写入会话收件箱**，不表示模型完成了指令；写入收件箱先于任务回执，两次存储之间崩溃可能重复投递，不保证恰好一次。（文档级）

## 5. 状态流转

- 三态：**活动 / 暂停 / 已结束**。活动才参与调度；暂停和已结束不再排期，但从时钟视图消失不等于被删除。（文档级）
- 结束只有两个自然条件：一次性任务的指令已持久写入收件箱；重复任务的最后一个发生时间点已过。（文档级）
- 改规则：任意状态都可改，保留任务 id 与已保存的投递记录；活动任务按新规则重排，暂停任务改完仍暂停，已结束任务保存新规则后重新变回活动。（文档级）
- 删除：任意状态可删；删除**清掉任务及其已保存的发送记录**，但**不删除相关会话**，也**不撤回已进入会话队列的消息**。（文档级）
- 编辑有乐观并发：提供 `expectedUpdatedAt` 与存储值不一致时返回 `schedule_conflict`；规则改变或显式恢复时重新计算未来时点。（文档级）

## 6. 归档边界（最易误判的一块）

| 场景 | 结果 | 证据 |
|---|---|---|
| 有活动任务指向该会话，普通归档 | 归档准入被 `workspace/session-activity` 挡下，`archiveSession` 报 `workspace/session-active`；**没有写入归档** | 文档级 |
| 对同一会话用 `stopActivity: true` 强制归档 | 跳过检查，先写入归档，再派发 `workspace/session-stop`；Schedule 提供方**删除**指向该会话的活动任务 | 文档级 |
| 任务目标通常是「每次新建对话」 | 原会话归档不影响后续运行，宿主仍按规则创建新会话 | 文档级 |
| 任务由该会话的 Agent 创建/修改、但目标在别的会话 | 任务保留，全局页面照常可见可管；会话行仍在，但活动时钟标识对归档行留空 | 文档级 |
| 目标会话已归档后按「立即执行」/`run` | 被拒 `schedule/target-archived`，UI 上禁用；到期投递时也再次检查归档状态 | 文档级 |
| 归档会话里的收件箱指令 | 归档会话被 `agent/pre-step` 门禁拦住，不会启动一轮模型处理去执行那条指令；取消归档后会话可继续 | 文档级 |
| 取消归档 | 不会恢复强制归档时被删除的任务 | 文档级 |

区分两个「被拒」：归档被拒发生在**归档之前**，是归档操作本身失败；`target-archived` 发生在**归档已经成功之后**，是任务没法向这个已归档目标投递/立即执行。两者不是同一个条件。

## 7. 历史与保留

- 回执记录 `scheduledAt`、`deliveredAt`、`messageId`、`targetSessionId`，还可含不可变的已发送 `prompt`；没有保存指令的旧记录不会被当前指令顶替。（文档级）
- 默认最多保留 200 条、30 天，同时保留最近一次回执；裁剪后更早记录标记为不可用，未保存的更早快照无法恢复。（文档级）
- 页面每次显示 20 条，可「加载更多」；记录按保存顺序从新到旧，不表示模型执行结果。（文档级）
- 只存在于旧 Session 日志里的提醒不会被自动调度，仍需重新创建；已删除的任务记录不会重建。（文档级）

## 最小验证

本机只读调用 `schedule_list`，返回分页对象 `{items, shown, total, limit, offset}`，条目含 `kind`、`title`、`rrule`、`target`、`status`、`lastDelivery` 等字段，确认工具可用、任务跨会话持久化、RRULE 与投递目标按文档结构存。安装版本由包 `package.json` 的 `version` 字段核对为 `0.2.2-rc.5`。文档在安装包内可直接读取，属文档级证据，未反编译源码。

## 未核实项

- 到期投递遇到已归档目标时的完整落库/回执行为：文档只明确「投递时再次检查归档状态」与 `run` 的 `target-archived` 拒绝，未给出全部分支。
- 两个 DSH 进程同时运行时 Schedule 可能重复投递或互相覆盖状态：来自前序实测记录（见 `Web进程-启动常驻与Desktop共存.md`），本次未复现。
- 强制归档删除活动任务时是否逐一清掉发送记录：文档明确「删除任务会清掉已保存记录」，但未单独描述归档停止路径的裁剪细节。
