# 聊天输出里成对的美元符号会被渲染成行内公式

## 一句话

在 DSH Web GUI 的**聊天回复**里裸写两个美元符号，渲染器会把它们配对成行内公式，吞掉符号本身并去掉公式内的空格。价格一律写成「0.13 美元」或转义的 `\$0.13`，不要裸写成对符号。

## 现象（已验证）

2026-11-26 一次回复里写了四个价格，渲染后变成：货币符号全部消失，成对符号之间的英文单词粘连（`DSV4.1Flash`、`ClaudeHaiku5.5`）。原文空格没丢，是公式渲染时忽略空格。

根因不是 Markdown 语法错误：标准 Markdown 里美元符号不是特殊字符，markdownlint-cli2 不会报任何错。这是渲染器（KaTeX / MathJax 一类行内公式）的方言行为。

## 规避（已落地）

- 价格写「0.13 美元」，或写转义的 `\$0.13`；表格单元格里的竖线、正文里的尖括号同样可能被吃掉，用代码包裹或转义。
- 规则已写入用户级 `~/.dsh/AGENTS.md` 的 `## Style`，每次会话自动加载，不依赖 skill 命中。

## Skill 能不能防（文档级）

skills.sh 上搜到的 markdownlint 类 skill（安装量最高约 130，源仓库仅 3 stars）工作方式都是 `npx markdownlint-cli2 "**/*.md"`，只扫磁盘上的 `.md` 文件，不检查聊天输出；而且标准 linter 不认为美元符号有问题，装了也防不住。

复核命令：`npx skills find markdown lint`。若 npm 缓存目录不在工作区会 EPERM，把 `npm_config_cache` 指到工作区内即可跑通。

## 已验证 / 文档级 / 未验证

- **已验证**：渲染错位现象（截图前后对照）；规则已写入 `~/.dsh/AGENTS.md` 且回读可见。
- **文档级**：skills.sh 搜索结果与 markdownlint 类 skill 的工作方式。
- **未验证**：Desktop / CLI 等其他 surface 是否同样处理；没有在别的渲染器上复现。
