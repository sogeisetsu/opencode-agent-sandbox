# 鹈鹕骑自行车：MiMo V2.6 Pro 版单时钟动画与运动学验证

## 对比对象

| 产物 | 模型 | 相对路径 |
|---|---|---|
| MiMo 版（本文件评测对象） | MiMo V2.6 Pro | [`../../evals/pelican-bike-basic-prompt/mimo-v2.6-pro.html`](../../evals/pelican-bike-basic-prompt/mimo-v2.6-pro.html) |

提示词原文与 Iceman / 混元 4 两版相同（登记表有存档）：`Generate an HTML file that renders an SVG of a pelican riding a bicycle`。首版是静态 SVG，同会话用户指出「当然应该把动画加上的呀」后在同一份文件上补循环动画（迭代方式同 Iceman 版）。产出会话 id 未记录（`—`）。

## 一句话结论

**单时钟 rAF + 显式 `rotate(deg cx cy)` + 两骨 IK**：脚-踏板偏差 0px、踏板净旋转 0°、两膝折向一致、曲柄/车轮周期比 **2.000 = 画出的齿比 26/13**、地面/轮面速度比 **1.000**、道路与云回绕无缝（已验证）。代价是两腿在牙盘前交叠、链条仍是直段虚线。

## 一、实现结构（已验证，源码）

常量：轮胎外缘半径 `RW=85.5`、轮周长 `CIRC=2π·RW≈537.212`、车轮周期 `PERIOD_W=1400ms`、曲柄周期 `PERIOD_C=2800ms`、曲柄臂 51、道路虚线间距 `TILE=CIRC/4≈134.303`、云间距/回绕模数 420。

- 单一时钟：`dist = CIRC * t / PERIOD_W` 连续增长不重置，所有图层从 `t`/`dist` 派生（同混元 4 版思路）。
- 轮子：`rotate(deg 250 420)` / `rotate(deg 570 420)` 显式轮心，**全程不用 CSS `transform-origin`** —— 规避 Iceman 版「`transform-origin: center` 按 viewBox 解析、轮子绕画布中心公转」（见 [`./鹈鹕骑自行车-Iceman版动画失效与验证方法.md`](./鹈鹕骑自行车-Iceman版动画失效与验证方法.md)）。
- 曲柄绕 BB `(395,438)` 转 `degC`，踏板 `rotate(-degC …)` 反向抵消 → 净旋转 0°，踏板保持水平。
- 脚在曲柄组外、只做 `translate`（活销位 − 静态锚点）→ 净旋转 0°、脚-踏板偏差 0px。
- 腿：两骨 IK（L1=95、L2=85），膝统一取 `perp=(uy,-ux)` 一侧 → 两膝折向一致（髋→踏板 × 髋→膝 叉积符号恒为 -1）。髋点随鹈鹕 bob（±2.2px）移动，IK 目标始终是活销位，腿根不脱身。
- 齿比自洽：曲柄/车轮周期比 **2.000** = 牙盘 r26 / 飞轮 r13（即画出来的尺寸）；链速 `26·ω_c = 13·ω_w = 58.34` 单位/s 双向核对（已验证）。地面/轮面 = 1.000。
- 回绕无缝：道路虚线 mod `TILE`、云 mod `420`，模数均等于各自图案间距，且图案均匀平铺。
- `prefers-reduced-motion: reduce` 时只 `draw(0)`、不启 rAF（同混元 4 版做法）。
- 轮辐 8 条 + 每轮单一气门嘴标记：打破 45° 自重合，避开混元 4 版「16 辐条在整数倍角度下截图误判没转」的采样陷阱。

## 二、验证（已验证）

静态校验：SVG 是良构 XML、19 个 id 无重复、`url(#sky)` 全解析、内联脚本 `node --check` exit 0。

运动学 360 采样 × 2 腿 = 720 点：不可达 **0**；髋→销距离 72.309..175.100（两骨上限 180）；两膝叉积符号 `{-1}`，折向一致。

DOM 探针（临时副本禁 rAF、固定 t 后 `--dump-dom`）：

```
t=0   : spokesR rotate(0 250 420) | crank rotate(0 395 438) | pedalA rotate(0 430 475) | footA translate(0.047 0.05)
t=200 : spokesR rotate(51.429 250 420) | crank rotate(25.714 395 438) | pedalA rotate(-25.714 430 475)
        footA translate(-19.499 11.587) | road translate(-76.745 0) | clouds translate(-15.349 0) | chainA dashoffset -7.338
t=700 : spokesR rotate(180 250 420) | crank rotate(90 395 438) | pedalA rotate(-90 430 475) | footA translate(-72.05 -1.953)
```

- `crank` 与 `pedalA` 角度始终互为相反数 → 踏板净旋转 0°（已验证）。
- `footA` 位移 = 销位移：t=200 销 (410.50, 486.59) − 静态 (430, 475) = (−19.50, 11.59)，与探针一致（已验证）。
- `road` 位移 = `dist` = CIRC·200/1400 = 76.745；`clouds` = 0.2·dist = 15.349（已验证）。
- 腿 `d` 逐帧重算，膝/脚坐标随销移动（已验证）。

像素 diff（1000×760，标准库 PNG 解码逐像素比较，真实输出）：

```
t0 vs t200  : 37016 px
t0 vs t700  : 24259 px
t200 vs t700: 42841 px
```

肉眼截图（t=200，无头 Chrome）：腿连接到踏板、膝前折、翅膀握在把套上、链条/道路/云渲染正常 —— Iceman 版「加了动画但一次没看」的流程问题在本版不存在。

## 三、仍有的不足（如实记录）

1. **两腿在牙盘前交叠**（已验证，截图）：远腿膝前伸幅度大，观感拥挤，与混元 4 版同类问题。
2. **链条是两条带 `stroke-dasharray` 的直段**（已验证，源码）：不绕牙盘/飞轮；dashoffset 按链速滚动是唯一运动。
3. **t=0 脚锚点与精确销位差 0.05px**（已验证）：`pinA0` 写死整数 (430,475)，精确销位 (430.047,475.050)（`TH0=atan2(37,35)`）；肉眼不可辨。
4. **静态兜底腿形与 draw(0) 差 <0.2px**（已验证，两组数字对比）：手写 `d` 膝点 (452.61,392.96) vs 计算 (452.613,393.100)；禁用 JS 时首帧仍正确（未做禁 JS 截图，标**推测**）。
5. **性能未实测**（推测）：未跑 CDP trace，不写耗时与掉帧结论。

## 四、给后续评测的提醒

1. 齿比不必照抄混元 4 版的 1.000：把曲柄/车轮周期比做成**画出来的牙盘/飞轮半径比**（本版 26/13=2.000）同样是自洽的，且物理上更真；判定看「周期比 == 画出的齿比」与「地面/轮面 == 1」，不是看数值是否等于 1。
2. 打破轮辐的旋转对称（加气门嘴等单标记）可以免掉「截图采样撞自重合」的误判，16 辐条的坑见混元 4 版笔记第六节。
