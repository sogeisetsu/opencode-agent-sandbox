# 键位：keybindings.json 只存覆盖，组合键是两段式

> 来源：本机 VS Code 1.143 实测记录。标 **待确认** 的是推断，未复核。

## 默认键位在哪看

`keybindings.json` 里只有你改过的覆盖项；默认键位在内核 bundle 和各扩展自己的 `package.json` 里。查看方式二选一：

- 命令面板 → `Preferences: Open Default Keyboard Shortcuts (JSON)`
- 快捷键 `Ctrl+K Ctrl+S` 打开键位编辑器

## 组合键是两段，不是同时按

`Ctrl+K Ctrl+0` 的按法是：按住 Ctrl 按 K → **松开全部键** → 再按 Ctrl+0。

推论：单独按 `Ctrl+K` 时**不应该有任何反应**。如果绑了东西，前缀组合全被吃。

## 把前缀键绑成普通命令会截断整族组合（已验证）

比如把 `ctrl+k` 绑成"清空终端"，所有 `Ctrl+K xxx` 都不能用了。想只在终端里生效，加 when 条件：

```json
{
  "key": "ctrl+k",
  "command": "workbench.action.terminal.clear",
  "when": "terminalFocus"
}
```

## 解绑要写完整组合

命令前加 `-` 表示解绑，但键位字符串必须和实际组合完全一致：写 `"ctrl+k"` 解不掉 `ctrl+k ctrl+c`，得写 `"ctrl+k ctrl+c"`。

## 和中文输入法抢键

- `Ctrl+Space` 与微软拼音的"中英文切换"冲突，直接改键（例如 `Alt+/`）更省事。
- `Ctrl+.` 可能被输入法的"中英文标点切换"吞掉 —— **待确认**。验证方法：切到英文输入状态再按，看是否触发。

## 折叠快捷键与光标位置

- 折叠命令按**光标位置**找折叠区域，不看选区。所以 `Ctrl+A` 全选后光标落在文件末尾，再按递归折叠什么也不会发生。
- 与光标无关的全量折叠：`Ctrl+K Ctrl+0`。
- 递归折叠/展开 = 连嵌套层一起处理；普通版只动当前层。
- 手动指定范围折叠：选中后 `Ctrl+K Ctrl+,`。
