# 扩展管理：禁用 ≠ 卸载，卸载会连带依赖，更新留残留

> 来源：本机 VS Code 1.143 实测记录。标 **待确认** 的是推断，未复核。

## 禁用和卸载不是一回事

禁用只是不加载，文件还完整躺在磁盘上，不回收任何空间。要腾地方必须卸载，可以批量清掉已禁用的那批。

## 卸载扩展包会连带卸载依赖项（已验证）

- 卸 `python-extension-pack`，`ms-python.python` 和 Pylance 一起被带走。
- 卸 Remote-SSH，连带干掉它依赖的两个扩展。

所以卸完必须复核实际剩了什么：

```powershell
code --list-extensions
```

## 扩展更新留下三类残留（已验证）

1. 旧版本目录（`<publisher>.<name>-<旧版本号>`）
2. `.uuid` 临时目录 —— 实测某扩展的三个各占约 800MB
3. `.obsolete` 清单，记录等下次启动删掉哪些

清理前必须**完全退出 VS Code**（含托盘/后台进程），否则文件被占用，删不干净也删不掉。

## 工作区级禁用存在哪（已验证）

不写进 `settings.json`，而是落在这条路径下的 SQLite 库里：

```
%APPDATA%\Code\User\workspaceStorage\<hash>\state.vscdb
```

`<hash>` 由工作区路径算出。含义：换机器、重新 clone 都不会带走这份禁用状态。想让设置跟着仓库走，只能写 `settings.json`。

## 三个容易想错的点

- `.vscode/extensions.json` 只有 `recommendations` / `unwantedRecommendations`，是**建议**不是强制，装了也不会自动装扩展。
- `extensions.disabled` 不是设置项。源码里同名的是遥测事件名，写进 settings 会被标成未知配置（Unknown Configuration Setting）。
- 内置扩展约 96 个，不能卸载；Copilot 可以禁用。查内置列表用 `@builtin`：
  ```
  命令面板 → Extensions: Show Built-in Extensions
  ```
