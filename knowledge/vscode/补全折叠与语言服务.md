# 补全、折叠与语言服务：哪些是内置，哪些靠扩展

> 来源：本机 VS Code 1.143 实测记录。标 **待确认** 的是推断，未复核。

## IntelliSense 是内置能力，不是扩展

但它按语言分发：每种语言由各自的 provider 提供。**内置**的只有 TS/JS、CSS、HTML、JSON、Markdown、PHP，其余语言靠语言扩展。

推论（已验证）：禁用 `cpptools` / `csharp` / `redhat.java` 后，那几门语言退回"按词补全"，现象很像"IntelliSense 挂了"，实际是 provider 没了。

## JS/TS 的折叠来自 tsserver

- `editor.foldingStrategy` 只决定按缩进还是按语法折叠，**与注释无关**。
- tsserver 的 `getOutliningSpans` 只认声明、变量语句、`return`、调用表达式和 EOF —— **不给文件开头、也不给紧跟在 import 前的注释**生成折叠区。
- 实测同一文件靠后的注释能拿到 comment span，开头的拿不到。
- 解法：`// #region` / `// #endregion`，或选中后 `Ctrl+K Ctrl+,` 手动指定范围。

## 补全 vs 代码操作是两套

| 触发 | 是什么 | 备注 |
|---|---|---|
| `Ctrl+Space`（或改键后的 `Alt+/`） | 补全列表 | 内置能力 |
| 小灯泡 / `Ctrl+.` | 代码操作（code action） | `quickFix` 只在真有修复项时才弹 |

## 三个命令容易混（查证：bundle 里的 id 与 kbOpts）

| 命令 | 默认键 | 内容 | 选中后 | 来源 |
|---|---|---|---|---|
| `editor.action.triggerSuggest` | `Ctrl+Space`，次要 `Ctrl+I` | 补全列表（成员/参数/变量名） | 插入文本 | 语言服务 |
| `editor.action.quickFix` | `Ctrl+.` | 代码操作菜单：quick fix + refactor | 改代码（多个编辑合并） | **所有扩展注册的 code action**（Copilot 就往这层塞） |
| `editor.action.sourceAction` | **无默认键** | "源代码操作"子菜单：整理导入、按导入排序、修复所有可修复的 JS/TS 问题、删除未使用代码、添加缺少的导入 | 批处理整份文件 | 语言服务 |

- `editor.action.sourceAction` 在 bundle 里只出现一次（定义处），没有任何键盘绑定 → 只能从菜单进。
- 它内部的 `editor.action.organizeImports` 单独绑了 `Shift+Alt+O`。
- 推论（已验证）：关掉 Copilot 后 triggerSuggest 和 sourceAction 一项不少，掉的是 quickFix 菜单里 Copilot 贡献的 `Modify` / `Review`。反过来小灯泡缺重构项，先怀疑语言扩展。

## Copilot 的 NES 不是 ghost text

NES（Next Edit Suggestion）改的是**已有代码**、可跨文件、行号槽有箭头提示；操作是先 `Tab` 跳到该处、再 `Tab` 接受。普通 ghost text 只是在光标处插新文本。
