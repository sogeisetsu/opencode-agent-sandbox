# 首次推送：从本地仓库到远程

## 全流程

> 草图：[`首次推送-两条路线.excalidraw`](./首次推送-两条路线.excalidraw)（OpenChamber 的 Files 视图里点开就是画布）

- **手动路线**：建远程（网页 / API）→ `git remote add origin <url>` → `git push -u origin main`。
- **一条命令路线**：`gh repo create <owner>/<name> --public --source . --remote origin --push`（用当前目录这个已有仓库，不重新 `init`）。

- `-u` / `--set-upstream`：让本地分支记住上游，以后直接 `git push` / `git pull`。
- `--source .` 用的是**当前目录这个已有仓库**，不会重新 `init`；`--push` 推当前分支。
- 手动路线等价：先建远程（网页或 API），再 `remote add`，再 `push -u`。

## 推送前的三个只读检查

```bash
git status --short --branch     # 工作区干净？在哪个分支？有没有上游？
git log --oneline -3            # 要推的是这几条提交？
git remote -v                   # 有没有已存在的 remote，别推错地方
```

## 会遇到的边界

| 情况 | 现象 | 怎么办 |
|---|---|---|
| 远程已有提交，本地是另一段历史 | `push` 被拒（non-fast-forward / unrelated histories） | 先 `fetch` 看差异；**不要**无脑 `--force`（会覆盖远程历史） |
| 推的分支名与远程默认分支不同 | 远程多出一个分支 | 明确要推的分支：`git push -u origin <branch>` |
| 推私有内容 | 推完就公开了 | **推之前**查一遍 `.gitignore` 和待提交文件 |

## 一句话

推是**不可逆**动作（尤其 public 仓库：别人可能已经抓到）。推之前先把 `git status`、`git log`、`git remote -v` 过一遍，比推完再回滚便宜得多。
