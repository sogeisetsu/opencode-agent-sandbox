# 本地目录名 vs 远程仓库名：它们没有关系

## 结论

- **Git 里根本没有"仓库名"这个概念**。本地只有一个 `.git` 所在目录（文件夹名），远程只有 URL。
- remote 只是 `.git/config` 里的一条**标签 + URL**，标签惯例叫 `origin`，叫别的也行。
- 所以：文件夹叫 `test`、远程仓库叫 `sandbox`、remote 标签叫 `origin` —— 三者互不约束。

> 草图：[`本地目录名与远程仓库名.excalidraw`](./本地目录名与远程仓库名.excalidraw)（OpenChamber 的 Files 视图里点开就是画布）

一句话：本地文件夹名只是路径，远程仓库名只是 URL 的一段，`.git/config` 里的 `origin` 是一个指向 URL 的标签——三者互不约束。

## 只读查证

```bash
git rev-parse --show-toplevel     # 本地"名字"其实就是这个路径的末段
git rev-parse --git-dir           # 通常就是 .git
git remote -v                     # 有哪些 remote、指向哪
git config --local --list         # 里面没有任何"仓库名"字段
```

## 改名/挪动文件夹会怎样

- **仓库内容不受影响**：`.git` 内部不记录主工作树的自身路径，改完照常用。
- 会失效的：**链接工作树**。它们的 `.git` 文件里写的是绝对路径，挪了之后用 `git worktree repair <path>` 修。
- 会变成孤儿：**按路径给项目派生 id 的外部工具**（会话记录、缓存目录常这么干）。换路径后旧 id 对应的缓存/工作树目录不再被关联（推测，未逐版本验证）。
- **不会自动同步远程**：远程地址要自己 `git remote add` / `set-url`。

## 常见误区

- ❌ "本地文件夹必须和远程仓库同名" —— 没这回事。
- ❌ "GitHub 上有同名仓库就不能推" —— 名字不冲突，真正的问题是**往一个已有内容的仓库推**会把两段无关历史混一起（需要 `--force`，一般别干）。
