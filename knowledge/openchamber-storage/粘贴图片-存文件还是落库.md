# 粘贴的图片：存成文件，还是 base64 直接落库

结论：这个开关是 **OpenChamber 自己加的**，不是 OpenCode 原生功能；两种存法代价完全不对称，是本地数据库膨胀的主要来源之一。

## 开关在哪

设置项 `savePastedImagesAsFiles`（i18n key `settings.openchamber.visual.field.savePastedImagesAsFiles`）。

## 开启时（存文件）

1. 前端调用 `writeOpenCodeTempFiles`，写入路径：

   ```
   {paths.tmp}/openchamber/<16 位随机 hex>/<原文件名>
   ```

   落到磁盘是经 OpenCode SDK 的 `file.write` 完成的。
2. 消息里只放一个**指向绝对路径的 markdown 链接**，聊天记录里没有图片数据。

怎么查 `paths.tmp`（只读）：

```bash
opencode api get /api/info        # 返回里带 paths.tmp
```

Windows 默认是 `%LOCALAPPDATA%\Temp\opencode`（OpenCode 2.0.x 实测）。

坑：

- **没有任何清理逻辑**。前端只写不删，删掉会话后图片就成了无人引用的孤儿文件，只能手动清，或等系统清理 temp。
- 换机/清 temp 之后，老会话里的图片链接会全部失效。

## 关闭时（base64 落库）

图片转 base64 塞进 `part.data`（file part），**永久留在数据库里**，体积比原文件大约多 1/3。删会话才跟着没。

## 特殊情况

模型不支持图片输入时，**无论开关怎么设**，都会强制走"存到文件 + 消息里放路径"这条路，不会做成 base64。

## 取舍

| | 存文件 | 落库 |
|---|---|---|
| 库体积 | 不涨 | 每张图永久占位，还放大 ~1/3 |
| 会话自包含 | 否（依赖 temp 目录） | 是 |
| 删会话后 | 留下孤儿文件 | 随记录删除 |

推荐开。代价是老会话图片链接在清 temp 后失效——能接受就开，同时记得 temp 里的 `openchamber/` 子目录需要自己定期清。

## 已验证 / 推测

- **已验证**：开关归属（OC 自加）、写入路径形状、经 SDK `file.write` 落盘、无清理逻辑、base64 放大比例、模型不支持图片时强制走文件路径、`/api/info` 能拿到 `paths.tmp`。
- **推测**：随机 hex 目录的具体生成方式（只确认了是 16 位 hex，未读生成代码）。
