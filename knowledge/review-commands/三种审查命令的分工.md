# 三种审查命令的分工：/review、/handoff-review、/workspace-review

命令列表里的条目按**来源**分两类，靠徽标区分：

- 徽标 **OPENCODE**：OpenCode 引擎自带，编译进 `opencode.exe`，不在 `~/.config/opencode/command/`，也不在 OpenChamber 的魔法提示词列表里。
- 徽标 **OPENCHAMBER**：OpenChamber 宿主自带，形态是"魔法提示词"（可见消息 + 隐藏指令），可以在设置里改。

## 对照表

| 名称 | 干什么 | 来源 | 形态 |
|---|---|---|---|
| `/review` | 启动一个专门做审查的子代理（subtask）审查改动。不带参数：`git diff` 看未暂存、`git diff --cached` 看已暂存、`git status --short` 找未跟踪文件；也可传 commit SHA（`git show`）、分支名（`git diff <branch>...HEAD`）、PR URL 或编号（`gh pr view` / `gh pr diff`）。会读完整文件补上下文，只审本次改动，找真实 bug、结构问题和明显性能问题并标严重程度 | 引擎内置，模板源码在 `packages/core/src/plugin/command/review.txt` | 内置斜杠命令 + 硬编码模板（subtask，跑在子会话里，不污染当前上下文）；界面改不了 |
| `/handoff-review` | 先让当前 agent 写交接（意图、改了什么、为什么、跑了哪些验证、遗留缺口），再据此新建或复用独立审查会话交给另一个 agent | OpenChamber 宿主 | 魔法提示词（id 形如 `session.reviewHandoff.visible` / `session.reviewHandoff.instructions`），可改 |
| `/workspace-review` | 直接审当前工作区 diff：先判断意图是否达成，再按 blocker / non-blocker / nit 分级列问题并指文件；只读不改 | OpenChamber 宿主 | 魔法提示词（id 形如 `session.review.visible` / `session.review.instructions`），可改；也作为审查会话的首条指令 |

一句话：`/review` 是引擎的通用 git 改动审查；`/workspace-review` 是宿主对"这次改动对不对、够不够"的评判；`/handoff-review` 是"先写交接、再交给独立会话"的流程编排。

## 怎么核实（已验证，2026-11-01）

- 引擎内置：`gh api repos/sst/opencode/contents/packages/core/src/plugin/command/review.txt` 能取到文件（约 4.6 KB），内容与上表描述一致（先判断输入类型、`git diff` / `git diff --cached` / `git status --short`、`gh pr view` 等）；同目录下只有 `initialize.txt`、`review.txt`、`schedule.txt` 三个模板。
- 宿主魔法提示词：在 OpenChamber 安装目录的 `resources/web-dist/assets/*.js` 里 grep `reviewHandoff`，能命中，且能提取出 `session.review.visible`、`session.review.instructions`、`session.reviewHandoff.visible`、`session.reviewHandoff.instructions`、`session.reviewSession.visible` 等 id。
- 不在用户命令目录：`~/.config/opencode/command/` 下没有 `review.md`。

## 纠错记录

之前有一轮说"没有 /review，只有宿主那几个"，是错的：列表里确实有 `/review`，只是徽标是 OPENCODE 而不是 OPENCHAMBER。判断命令归属时先看徽标和来源，别只看名字像不像宿主命令。

**推测**：模板源码路径属于上游当前布局，后续版本若挪动目录，以仓库实际文件为准。
