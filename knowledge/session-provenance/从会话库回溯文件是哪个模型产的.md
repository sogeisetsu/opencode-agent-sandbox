# 回溯某个文件是哪个模型产出的（查会话库）

场景：仓库里躺着一个 `index.html`，没人记得是哪个模型、哪次跑出来的。OpenCode 的会话库能回答，只要文件内容还在消息里。

结论（已验证）：能查。做法是把会话里所有完整的 HTML 块抽出来，和磁盘文件做**行级 Jaccard 相似度**，第一名和第二名差一个数量级就是它。

## 数据在哪

`~/.local/share/opencode/opencode.db`（SQLite）。V2 schema 两张表：

- `session_v2`：`id` / `title` / `model`（JSON：`{"id":…,"providerID":…}`）/ `time_created`（epoch ms）/ `project_id`
- `project`：`id` / `worktree`（该会话的工作目录）
- `session_message`：`session_id` / `type`（`user` / `assistant` / `synthetic` / `tool` …）/ `seq` / `data`（JSON）

V1 库是 `session` + `message`，没有 `type` 列。先探 `sqlite_master` 里有没有 `session_v2` 再决定读哪套。

`type=synthetic` 是上下文快照/摘要，里面也可能整篇夹着文件内容，算"某时刻它长这样"的旁证。

## 关键坑

1. **`project.worktree` 不一定是仓库根**。multi-run 的每个模型跑在自己的 worktree 里（`~/.local/share/opencode/worktree/<hash>/<dir>`），按仓库路径过滤会漏掉这些会话。要么两边都匹配，要么干脆全库扫。
2. **最终版本可能不以整篇形式存在**。模型写完文件后如果再用 edit 工具改，库里只有首版整篇 + 一堆 `oldString/newString`。这时先用首版定位模型（相似度高），再用**只在改后版本里出现的特征行**（例如某个改过的常量）确认修订发生在同一个会话里。
3. **换行符**。库里的字符串是 LF，磁盘上可能是 CRLF；比较前统一 `\r\n → \n`，否则逐字节哈希全不匹配。
4. 逐字节 md5 常常一个都命中不了，**别指望精确匹配**，直接用相似度排序。
5. PowerShell 里 `bun -e "…"` 的嵌套引号会被吃掉，脚本写成临时 `.mjs` 再 `bun <file>` 跑。

## 脚本骨架（只读）

```js
import Database from 'bun:sqlite';
import { homedir } from 'os';
const db = new Database(`${homedir()}/.local/share/opencode/opencode.db`, { readonly: true });

const ours = await Bun.file('<file>').text();
const A = ours.replace(/\r\n/g, '\n');
const linesA = new Set(A.split('\n').map(l => l.trim()).filter(Boolean));

for (const s of db.query(`SELECT s.id, s.model, s.time_created, p.worktree AS project
                          FROM session_v2 s LEFT JOIN project p ON p.id = s.project_id`).all()) {
  for (const r of db.prepare('SELECT type, data FROM session_message WHERE session_id = ?').all(s.id)) {
    const d = JSON.parse(r.data);
    const blobs = [];
    const walk = o => typeof o === 'string'
      ? (o.includes('<!DOCTYPE html>') && o.includes('</html>') && blobs.push(o))
      : (o && typeof o === 'object' && Object.values(o).forEach(walk));
    walk(d);
    for (const b of blobs) {
      const B = b.replace(/\r\n/g, '\n');
      const linesB = new Set(B.split('\n').map(l => l.trim()).filter(Boolean));
      const shared = [...linesB].filter(l => linesA.has(l)).length;
      console.log(((shared / (linesA.size + linesB.size - shared)).toFixed(3)), s.model, s.title);
    }
  }
}
```

## 实测结果（同一个任务 10 个模型）

同一个提示词（章鱼骑自行车的 SVG 动画）跑过 10 个模型，磁盘文件 vs 各模型产出的行级 Jaccard：

| 模型 | 相似度 |
|---|---|
| DeepSeek V4.1 Flash | **0.911** |
| GLM-5.2 | 0.035 |
| Step 5 Preview Free | 0.034 |
| MiMo-V2.6-Flash | 0.029 |

第一名的字符数和磁盘文件只差 59，其余全在 0.04 以下 —— 结论没有歧义。剩下的差异不是别的模型，而是**同一会话后续轮次用 edit 改的**（修触手路径的 `M` 拼接、把围巾挪到身体后面、按用户反馈把曲柄从逆时针改成顺时针）。所以"是哪个模型做的"要连"谁后来又改过"一起回答，光比对首版会得出"不像任何一个"的错误结论。
