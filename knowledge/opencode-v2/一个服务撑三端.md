# 一个后台服务撑起三个前端

## 一句话

TUI、内嵌 web UI、Desktop GUI 都只是 **client**；真正持有会话 / 配置 / 权限 / 工具执行的是一个**共享后台 server**，而且它比任何一个 client 活得久。

> 草图：[`三端一服务.excalidraw`](./三端一服务.excalidraw)（OpenChamber 的 Files 视图点开就是画布）

## 三个前端

| 前端 | 形态 |
|---|---|
| TUI | 终端全屏界面（`opencode`） |
| Web UI | server 自带，浏览器打开 |
| Desktop GUI | Electron 应用 |

三者都是同一个 server 的 client。关掉 TUI 不影响 server 继续跑。

## server 的几种形态

- 默认：自动发现或启动一个"你账号下的共享后台服务"，所有本地 client 连它。
- `--standalone`：跟当前进程同生共死的**私有** server。
- `--server <url>`：连到指定 server。
- `opencode serve`：**前台常驻**同一个 server（适合 systemd / Docker / 远程主机 / 想要独立 server 的场景）。

## 关掉共享 service 的代价

- `opencode service set disabled true`：默认不再用共享 service（私有 server 变成默认）。
- 代价：**pair 需要共享 service**，禁用期间不可用。
- 恢复：`opencode service unset disabled`；`opencode service start` 仍可显式启动共享 service。

## Desktop 跑的就是内置 CLI 当 server

Desktop 把打包进来的 CLI 二进制 stage 后以 server 方式拉起（sidecar）。所以"桌面版里其实跑着一份 opencode server"这句是对的。

> 已知现象（供参考，非本机复现）：把 `--standalone` 的独立 CLI 与 Desktop 指向同一数据目录时可能互相打架。

## 生命周期

- **按需启动**：不跑 client 就不启动。V2 源码里搜登录项 / LaunchAgent 一类自启机制无命中 —— 注意这是"没找到证据"，不等于绝对不存在。
- 关掉终端或 TUI：server 还在，重开 client 直接连上。
- 重启电脑后：server 不自启，跑任意 client 或 `service start` 即可拉起；登录 cookie 仍在，**不用重新 pair**。

## service 文件与路径（官方 troubleshooting）

| 用途 | 位置 |
|---|---|
| 共享 server 登记 | `~/.local/state/opencode/service.json` |
| 私有 service 配置 | `~/.config/opencode/service.json` |
| 数据库 | `~/.local/share/opencode/opencode.db`（`OPENCODE_DB` 可覆盖） |
| 日志 | `~/.local/share/opencode/log/opencode.log`（每行带 `run` id 与 `role`） |

诊断命令：

```bash
opencode service status          # 当前地址、状态
opencode service restart|stop|start
opencode api get /api/info       # 健康检查，含 pid
opencode debug paths <selector>  # 只打印路径；不启动 server
```

`debug paths` 的 selector 可选 `db` / `home` / `data` / `config` / `cache` / `state` / `tmp` / `bin` / `log` / `repos`；省略则打印全部并带标签。

官方警告：排查时**别直接删/改** service 文件或数据库，用 service 命令管理。

## 已验证 / 随时间变化

- 已验证（官方文档）：三端一服务、`--standalone` / `--server`、`service set disabled`、service 文件与路径、`debug paths` selector。
- 已验证（源码）：Desktop 以 sidecar 方式跑内置 CLI 当 server。
- **随时间变化**：包结构与命令细节会变。
