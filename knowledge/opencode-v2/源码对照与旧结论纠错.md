# 源码对照：几条"旧结论"的纠错

## 一句话

把一份早先的"OpenCode V2 知识汇总"逐条对照 **V2 源码 + 官方 v2 文档**后，有 **4 处**当时标着"推测 / 没找到证据"的结论现在能给出确定性答案，其中两条是**反过来的**。

> 核对对象：**V2**。V2 的源码在仓库的 `dev` 分支，包结构是 `packages/{cli,tui,server,core,app,gui-extensions,desktop,...}`。**本文一律不引用 V1 的源码**——V1 是另一套布局，顺着它搜会得出错误结论（见文末）。

## 纠错 1：Desktop **有**内嵌终端

- 旧说法：搜 `xterm` / `node-pty` 只命中 WSL 运行时 → 判为"没找到证据"。
- 事实：`packages/gui-extensions/src/terminal/` 是一整套内建终端扩展（`terminal.tsx` / `panel.tsx` / `tab.tsx` / `model.ts` / `state.ts` / `serialize.ts`）；gui-extensions 的 README 明确把 **terminal 列进 desktop 与 web 应用的内建扩展**；e2e 里也有 `terminal-input.spec.ts`、`terminal-benchmark.spec.ts`。
- 教训：只搜 `xterm` / `node-pty` 会漏。终端 UI 在 `gui-extensions` 包，底层 pty 在 `packages/core/src/pty/`。**搜关键词的"没有"极不可靠。**

## 纠错 2：staged CLI 现在会清理

- 旧说法：每次更新 stage 一份二进制、**从不清理**，每次约 175MB。
- 事实：`packages/desktop/src/main/service/cli-stages.ts` 的 `cleanStages` 会**删除非当前** stage 目录；stage 目录同时改成按 `<version>-<arch>` 分。Windows 上删不掉"尚未退出的 exe"会记日志、下次启动重试。
- 教训："没有清理逻辑"这类判断会被后续版本修掉，引用前必须重新看源码。

## 纠错 3：30 天会话是硬编码，不是"没找到开关"

- 旧说法：30 天是否可配 → "没找到开关"。
- 事实：`packages/server/src/auth.ts` 里 `SESSION_TTL_SECONDS = 30 * 24 * 60 * 60`，**硬编码常量**，无 env / config 入口 → **不可配**。
- 附带确定结论：会话 token = `expires.HMAC(password)`，所以改密码即全端登出；cookie 名带端口。

## 纠错 4：能不用配对链接，手输地址 + 密码连

- 旧说法：web UI 页面是否有手输密码表单 → "未验证"。
- 事实：`packages/app/src/servers/connect/screen.tsx` 的连接屏有 `link` / `password` 两套方式；手动填服务器地址 + 密码即可连（"add server" 对话框里也有密码字段 `dialog.server.add.password`）。

## 对得上、但源码路径是 V1 的

- 旧汇总的"来源地图"（如 `packages/opencode/src/cli/cmd/tui`、`packages/opencode/src/server/shared/ui.ts`）属于 **V1 的布局**，不是 V2。
- V1 与 V2 是同一产品的两套布局：V1 是较旧的单体结构（`packages/opencode` 里装着 CLI/TUI/服务端）；**V2 已拆开**成 `packages/{cli,tui,server,core,app,gui-extensions,desktop,...}`（TUI 在 `packages/tui`，CLI 在 `packages/cli`，服务端在 `packages/server`+`packages/core`，桌面与网页 GUI 能力在 `packages/{desktop,app,gui-extensions}`）。
- **别把 V1 的源码路径当 V2 用**——这是本次对照里最容易被误导的地方（顺着 V1 的路径去搜，会得出"功能不存在"的错误结论，纠错 1 就是这么来的）。
- 结论：引用源码路径要**写清是 V1 还是 V2**，并带上核对时间。

## 仍然只能给"没找到证据"的

- server 是否**绝对**没有开机自启：在 V2 源码里搜登录项 / LaunchAgent 一类无命中，但"搜不到"不等于"不存在"。
- 终端扩展的具体能力边界（多标签、会话持久化等）：终端存在已确认，细节未逐项复现。

## 怎么复核（只读）

```bash
# 直接看线上当前源码（不 clone）
gh api repos/<owner>/<repo>/contents/<path> -H "Accept: application/vnd.github.raw"

# 或本地 clone 后锁定当前修订
git -C <repo> log -1 --format="%H %ci %s"
```

路径用占位符；本机路径不写进这里。
