# 指令注入的四种时机：常驻、条件、按需、角色

> 核对：2026-11-02。路径与行为来自 VS Code 官方文档（2026-10 版）与 OpenCode 官方文档；没实测的标 **推测**。

## 为什么要按「注入时机」分类

按文件名分类（instructions / agents / skills）只是表面。真正影响 token 成本和行为的，是**它什么时候进入上下文**：

| 时机 | 形态 | 什么时候进上下文 | 成本 |
|---|---|---|---|
| 常驻 | `AGENTS.md`、`copilot-instructions.md` | 每次请求 | 全量、一直付 |
| 条件 | `*.instructions.md` 的 `applyTo` glob | agent 碰到匹配文件时 | 按命中付 |
| 按需 | `SKILL.md` | 平时只露 name + description，调用 `skill` 工具才载入正文 | 名字级，很小 |
| 角色 | agent 文件（`.agent.md` / `.md`） | 选中/派发该 agent 时，作为它的系统提示与权限集 | 每个角色一份 |

第四类不是「更多指令」，是**换执行主体**：模型、工具、权限都跟着 agent 文件走。把它当 instructions 用，会出现「规则写了但工具没开」的错配。

## 三类路径对照（已验证）

### VS Code / Copilot

| 类型 | 工作区 | 用户级 |
|---|---|---|
| 常驻指令 | `.github/copilot-instructions.md`、`AGENTS.md` | `~/.copilot/copilot-instructions.md` |
| 条件指令 | `.github/instructions/**/*.instructions.md`（frontmatter `applyTo`） | `~/.copilot/instructions/*.instructions.md` |
| agent | `.github/agents/*.agent.md`（也认 `.md`） | `~/.copilot/agents`、`~/.claude/agents` |
| skill | `.github/skills/` 一类目录（**推测**，本次未核对具体路径） | `~/.copilot/skills/`（**推测**） |

### OpenCode

| 类型 | 工作区 | 用户级 |
|---|---|---|
| 常驻指令 | 当前目录向上找到的 `AGENTS.md` | `~/.config/opencode/AGENTS.md` |
| 追加指令 | `opencode.json` 的 `instructions[]`（可写路径、glob、URL） | 同一字段，全局配置 |
| agent | `.opencode/agents/*.md` | `~/.config/opencode/agents/` |
| skill | `.opencode/skills/<name>/SKILL.md`、`.agents/skills/`、`.claude/skills/` | `~/.config/opencode/skills/` 等 |

OpenCode 的 `instructions[]` 在官方文档里的原话是「Additional paths or URLs supplying ambient instructions」，示例里就能写 `.cursor/rules/*.md`、`packages/*/AGENTS.md` 这类 glob。所以「Copilot 用 glob、OpenCode 只用目录层级」这个说法**不准确**：两者都能用 glob，差别在于 OpenCode 的 `AGENTS.md` 是目录发现，Copilot 的条件指令必须显式写 `applyTo`。

## 叠加，不是覆盖

- VS Code 官方文档：多个 applicable instruction sources 是**叠加**的，没有优先级，别靠顺序解决冲突。
- OpenCode 官方文档：`All instruction files are combined with your AGENTS.md files.`
- 例外：VS Code 的 **Copilot harness** 下，自定义 agent 的指令会加进 custom instructions，**冲突时 agent 优先**（官方原文 `take precedence if they conflict`）。
- 结论：常驻规则之间去重靠人；不要指望「后面写的覆盖前面」。

## `AGENTS.md` 是跨工具的共同分母

Copilot、Codex、OpenCode（以及一堆兼容实现）都读它，适合放「所有 agent 都该遵守」的规则：构建/测试命令、目录约定、禁改文件。

工具特有规则再放各自的位置：

- 只对某类路径生效 → Copilot 用 `applyTo`，OpenCode 用 `instructions[]` 里的 glob。
- 需要独立工具集/模型/权限 → 写 agent 文件，别塞进 AGENTS.md。
- 只在做某件事时需要的长流程 → 写 `SKILL.md`，靠 name+description 让模型自己决定要不要载入。

## 坑

- **改完不生效**：部分实现不热加载已修改的嵌套配置，改完要新开会话（**推测**：本次没逐个 harness 验证）。
- **嵌套 AGENTS.md 的语义**：OpenCode 文档只说从当前目录向上查找、「每个类别第一个匹配的胜出」，没明说多层是合并还是就近覆盖。别照抄「就近覆盖」，用前先实测（**推测**）。
- **条件指令与常驻指令冲突**：叠加后行为不可预测，必须人工去重。
- **agent 文件写太多背景知识**：每次选中都全量注入；长知识应放 skill，agent 文件只留角色与约束。
