# 配置块是覆盖层：删了会怎样（已实测）

## 一句话

`opencode.jsonc` 里那个 `opencode-go` 块的实际效果 = **换成一个等价端点 + 把可见模型钉死在 29 个**，没新增任何东西；删掉它是安全的（已端到端实测）。

## 覆盖了什么（catalog vs 你的配置）

| | catalog 内置 | 你的 `opencode.jsonc` |
|---|---|---|
| baseURL | `…/inference/go/openai/v1` | `…/zen/go/v1`（同网关别名） |
| 模型 | 32 | 29（钉死） |

- 你的 29 个**全部**在 catalog 的 32 个里，**config 独有 = 0** —— 覆盖层一个模型都没加。
- catalog 比配置多 3 个：`cat-jam-free`、`minimax-m2.7`、`step-5-preview-free`。
- 线上实际 37 个（比 catalog 还多），你的 29 模型清单**挡住了 8 个**，含 `qwen3.7-max`。

结论：覆盖层净效果 = 换个等价端点 + 砍掉 8 个可见模型。

## 删掉配置块安全吗（逐条依据）

| 担心 | 实测结论 |
|---|---|
| provider 会消失吗 | 不会，是内置的 |
| 端点会坏吗 | 不会，回落端点 `/inference/go/openai/v1` 实测可用（真补全 200） |
| 模型会丢吗 | 不会，你用的 29 个一个不丢 |
| 凭据受影响吗 | 不受影响（`integrationID=opencode` 共用；且删配置本来就碰不到凭据） |
| 有什么变化 | 只是**多暴露** 3（或 8）个模型 |

**提醒**：OpenChamber 一直在重写这个文件。删掉后如果被写回，说明这个 provider 是**它建的**，得从 OpenChamber 侧动手（见 `OpenChamber如何管provider.md`）。
